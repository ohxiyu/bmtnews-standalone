比特币完成首笔量子安全主网交易，约700万枚BTC仍面临风险

8月26日，比特币主网确认了首笔量子安全交易，该交易使用StarkWare研究员Avihu Levy提出的QSB（Quantum-Safe Bitcoin）方案，并经MARA的Slipstream服务纳入区块964,199。该交易以哈希安全性取代椭圆曲线签名，且无需更改共识规则。

这是首次在实际主网中证明，比特币持有者无需等待协议升级，即可将资金迁移到抗量子的花费条件。但该事件也凸显出约700万枚公钥已暴露的BTC仍处于风险之中，说明更全面的软分叉迁移路径仍有必要。

QSB的原理是反复调整候选交易数据，直到签名哈希符合比特币的验证规则，从而将安全性从椭圆曲线密码学转移到哈希函数逆向难度，据称对Shor算法具有约118比特的抗性。该交易符合共识规则，但不符合节点默认策略，需通过Slipstream直接提交给矿企MARA，成本达数百美元。

背景、讨论与参考资料

市场影响

该事件主要是一项技术概念验证，没有直接的价格传导机制，但可能影响机构对比特币长期量子风险的情绪。如果QSB这类迁移方案的需求增长，MARA的Slipstream等处理非标准交易的服务使用量可能上升，但高昂成本和非标准状态目前限制了规模。

背景

大多数比特币地址在首次花费之前，公钥都被隐藏在哈希之后，这为量子计算机攻击者推导私钥之前留出了一个时间窗口。QSB正是利用这一窗口，在经典公钥暴露之前构建基于哈希的花费条件。约700万枚BTC被认为已经暴露，因为其公钥已经可见，例如P2PK输出、Taproot输出以及重复使用的地址。未来拥有Shor算法的量子攻击者可以直接针对这些公钥发起攻击。

CryptoJS 随机性缺陷导致至少 569 万美元钱包种子失窃

区块链安全公司 Coinspect 披露，至少五款加密钱包（RRWallet、Bexo、NanChat、Bitcoin Libre 和 Milo）在生成恢复短语时使用了 CryptoJS 库中一个弱随机数生成器，导致资金可被攻击者预测。自 5 月以来，可追踪的损失至少达到 569 万美元，且偷窃行为发生在多轮攻击波中。

恢复短语相当于钱包的主密钥，因此可预测的生成过程意味着攻击者可以重建短语并盗走资金。该事件表明，一个广泛使用的 JavaScript 库如何使多个区块链上的用户暴露于风险中，而且受影响的钱包可能不止这五款应用。

存在漏洞的 CryptoJS.lib.WordArray.random() 函数将有效搜索空间从 2^128 或 2^256 种可能性降低到约 2^39 和 2^47，使得种子可以被逐一枚举。超过 2000 个种子在比特币、以太坊、波场、Rootstock 和 Polygon 上活跃，而 569 万美元只是一个下限；部分受影响应用已停止运营或在后续版本中修复。

rss · CryptoSlate · 8月27日 22:40 · 单一来源

背景、讨论与参考资料

市场影响

被盗资金分布在比特币、以太坊、波场、Rootstock 和 Polygon 上，攻击者可能将其变现，从而在这些市场增加潜在抛售压力。这一披露还可能降低用户对依赖 CryptoJS 的钱包的信任，提高对自托管安全风险的认知，进而影响用户行为和市场情绪，但并不意味着具体价格走向。

背景

恢复短语（或种子短语）是由钱包的熵生成的单词序列，所有私钥都由其派生而来；任何人获得它就能控制钱包。它本应非常随机，使得猜测在计算上不可行。CryptoJS 是一个流行的 JavaScript 加密库，其 WordArray.random() 中的弱实现是在 2014 年 6 月尝试增强随机性时引入的，该漏洞被分配为 CVE-2026-71851。

Cloudflare 优化 1.1.1.1 DNS 缓存，节省 100 TB 内存

Cloudflare 工程师在一篇技术博客中详细介绍了如何通过重构 1.1.1.1 DNS 解析器缓存中的数据结构与内存分配策略，在整个边缘网络节省了 100 TB 的内存。这项优化显著降低了每个缓存记录的开销。

该优化的意义在于展示了在关键互联网基础设施中，细致的系统级优化能够带来巨大的效率提升，从而降低硬件成本与能源消耗。这些技术也适用于其他高吞吐、内存受限的服务，并且证明了底层编程专业技能依然至关重要。

该优化主要通过重新组织缓存键与记录在内存中的布局，来减少每条记录的内存开销。评论者还指出，缓存行对齐与 slab 式分配可进一步减少碎片化并提升 CPU 缓存性能。

hackernews · TangerineDream · 8月28日 01:17 · 社区讨论 · 单一来源

背景、讨论与参考资料

背景

DNS 解析器缓存会保存最近解析过的域名查询结果，以便在收到重复查询时无需再向上游权威服务器请求。内存占用之所以重要，是因为 1.1.1.1 在 Cloudflare 全球边缘网络上以极大规模运行，每条记录省下几十字节就可能在全球范围内累积成 TB 级的内存节约。这类优化常用的底层技术包括 slab 分配器（通过缓存预创建对象来减少碎片并加速分配）、缓存行对齐（让数据访问对 CPU 更友好），以及基数树等节省空间的字符串键数据结构。

社区讨论

评论者总体持正面态度，有人称赞 Cloudflare 在产品和业务稳定盈利之后才着手优化成本的做法。多位专家提出了技术建议与质疑：一位 C 程序员建议将记录数据直接放在缓存条目元数据之后；另一位担心把多个独立的 Vec 合并为一个并通过偏移访问会削弱 Rust 的越界检查安全保证；还有人指出，对于主机名这种键，基数树可能比哈希表更省内存。
