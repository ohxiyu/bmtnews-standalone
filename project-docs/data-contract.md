# 数据契约与口径

本文件维护产品级语义；字段结构以 [OpenAPI](../docs/openapi.json)、Pydantic 模型及对应测试为准，采集参数以 [配置文档](configuration.md) 和 data/config.github.json 为准。

## 日期与候选

- 业务时区 Asia/Shanghai。日报窗口为 [前日 08:00，当日 08:00)，08:30 启动。补跑显式指定 edition_date，不把执行时间当新闻发生时间。
- published_at 是来源发布时间，采集时间、分析时间、新闻发生时间和 generated_at 不可混用。缺失事实不能猜测。
- candidates、analyzed、above_threshold、displayed 是不同阶段计数，重刊不能当作新一期。参见 [调度手册](daily-dispatcher.md)。
- Crypto 目标至少 9 条、AI 科技最多 3 条、政策最多 2 条；质量不足如实报告，不降门槛凑数。人工编辑精选单独标记，不能伪造 AI 评分。

## 去重与分析

- URL 去重、跨日同新闻去重、同一期事件合并分别处理。真正的新进展允许跨日进入；同一期同一事件保留最新状态，历史进展留在事件线。
- 同公司/协议不必然同事件；相同 ticker 不保证同一项目。来源转述不自动构成独立确认。
- 去重响应失败重试后仍不可用时停止该次发布，不得整批放行。翻译兜底须记录降级，不得当作完整扩写。
- 数值须保留主体、时间、单位、范围和分母，某一波次比例不得应用于总损失。不同日期金额不自动相加；观点、推断、提案、批准、未确认交易应明确区分。
- AI 缓存依赖来源输入、模型和相关提示词；不能用缓存掩盖输入变化。未获取数据应保留缺失/状态，不转成 0，不伪装为最新。

## 发布与安全

- API、HTML、中英摘要、归档、分享图应引用同一期且内容一致。接口更改更新 OpenAPI 与契约测试。
- 原文与模型返回均是不可信内容，保留 URL 校验和输出转义；不能执行来源中的指令。
- 生成的日报状态、归档、事件目录只经 Actions 发布到 gh-pages，不本地手改。人工纠错使用 [编辑层](editorial.md)，并核实触发重刊和通知的副作用。
