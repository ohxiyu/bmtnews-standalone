# Multiple Codex Collaboration

This repository uses GitHub as the coordination layer for every Codex session.
`origin/main` is the canonical codebase. Task branches are temporary, and
`gh-pages` is generated by automation.

## Start a new Codex task

From the primary repository checkout, create one isolated worktree per task:

```bash
git fetch origin
git worktree add ../bmtnews-feed-cost \
  -b agent/feed-cost origin/main
```

Open `../bmtnews-feed-cost` in the Codex session responsible for that task.
Use a different directory and branch name for every other Codex session.

Give the Codex session this instruction:

```text
Read and follow AGENTS.md before changing files.
You own only the current task branch and worktree.
Do not switch to, commit to, push to, or merge main.
Do not edit gh-pages.
Before opening the PR, merge the latest origin/main, run the required tests,
push the task branch, and open a PR targeting main. Do not merge the PR while
required checks are pending or failing.
```

## Work on the task

The Codex session should confirm its branch and scope before editing:

```bash
git status -sb
git branch --show-current
git fetch origin
```

It should commit only files that belong to the task and then push the task
branch:

```bash
git add path/to/changed-file
git commit -m "Describe the focused change"
git push -u origin agent/feed-cost
```

The pull request must target `main`.

## When another pull request merges first

Suppose `agent/frontend-speed` and `agent/feed-cost` were created from the same
version of `main`, and the frontend pull request merges first. Before the
feed-cost pull request can merge, update its branch:

```bash
git fetch origin
git merge origin/main
uv sync --frozen --extra dev
uv run pytest
git push
```

Resolve any Git conflicts in the task branch. A clean Git merge does not prove
that the combined behavior is correct, so run the tests after syncing.

If two tasks modify the same core file or one depends on the other, do not run
them in parallel. Merge the first task, then create the second branch from the
new `origin/main`.

## Merge and clean up

Merge pull requests one at a time after the required checks pass. After a pull
request is merged, run the cleanup from the primary repository checkout:

```bash
git fetch origin
git worktree remove ../bmtnews-feed-cost
git branch -d agent/feed-cost
```

## Branch responsibilities

| Branch | Owner | Purpose |
| --- | --- | --- |
| `main` | GitHub merge workflow | Canonical application source |
| `agent/<task>` | One Codex session | Temporary task implementation |
| `gh-pages` | GitHub Actions only | Generated state and deployed site |

No Codex session should use `gh-pages` as a development branch or merge it
back into `main`.
