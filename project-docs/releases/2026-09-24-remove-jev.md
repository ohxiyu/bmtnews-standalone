## 历史对照和行为变化

| 接入点 | 基线实现 | 本次结果 |
| --- | --- | --- |
| 评分与分类 | `src/ai/analyzer.py` 的 `_analyze_item` 使用同一次生成模型调用返回直接 0–10 分与分类；`src/ai/prompts.py` 有 0–2 至 9–10 的校准锚点 | 删除双 0–5 加权评分，恢复直接评分；生产门槛基线与当前均为 7.0 |
| 初筛 | `src/ai/prefilter.py` 生成模型批量初筛；失败时保留候选交给完整分析 | 恢复原路径，不以初筛失败给出替代分数 |
| 去重 | `src/ai/topic_dedup.py` 对已聚类新闻使用生成模型比较，两次尝试并校验 JSON；URL 去重及事件线另在 orchestrator/event pipeline | 恢复原比较、原有脱敏诊断及事件关系语义；移除独立评估模型和 503 拆批 |
| 去重失败 | 基线 `duplicate_groups` 在两次失败或 401/402/403 后抛出 `RuntimeError`，明确拒绝发布未检查内容 | **仍停止该次发布**，并保留脱敏 `dedup_diagnostic` warning 日志；不是跳过语义去重继续 |
| 生成后核验 | 基线 `src/ai/enricher.py` 没有独立模型核验；生成模型直接扩写、搜索引用 URL 限于真实搜索结果，失败回退翻译 | 移除所有独立核验调用和核验后剔除；保留新闻式提示、原文标题及可选内容/标签的后续独立改进 |
| 缓存 | 基线分析缓存含模型、提示词和来源输入 | 新的 `generation-direct-scoring-v1` 键将旧评估分数与当前分数隔离；生产 30 天 TTL 自然淘汰，不手改缓存分支 |
| 来源标识 | 基线无逐条分数来源字段 | 新分析条目/缓存/归档记录 `score_model`，运行报告汇总 `score_models`；历史分数不重写 |

基线中不存在独立的生成后事实核验，因此移除后系统**不再具备该能力**。来源支持仍依赖写作提示与搜索 URL 白名单，不能声称文章已经过独立事实查证。扩写失败的 `enrichment_degraded` 是基线已有的真实降级指标，继续保留；只服务于被删除核验门的字段不再生成。

## 迁移影响与人工步骤

- 分数虽仍显示 0–10，但打分方法从两个 0–5 项的加权换算，改回生成模型直接 0–10；不能把新旧均值当同一校准样本。历史归档原分数不变，新归档才记录评分模型。周报如混合新旧期，需注明评分器切换；首期人工检查达标数量、排序、同事件重复、低信号保底及背景/影响/引用覆盖率。
- 生产阈值 7.0 与基线相同，无需配置迁移；首次上线会对当前候选重新分析，不清空历史队列或手工触碰缓存分支。
- 代码实际引用的 GitHub Secret 为 `AI_GATEWAY_API_KEY`。PR 合并并确认不再有其他仓库用途后，仓库管理员可手动删除；本 PR 无法也不会删除 Secret。
- `pyproject.toml` 与 `uv.lock` 从未列入 TypeSafe SDK，调用使用已有 HTTP 客户端；因此不改依赖与锁文件。
- 回退：如获授权，可 revert 本 PR 恢复此前接入，再按仓库流程验证；不得直接改 `main` 或清空队列。
