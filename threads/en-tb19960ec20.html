    Firo's Urgent Hard Fork Fixes Spark Flaw That Could Allow Endless Token Creation

    Firo is carrying out an urgent hard fork that activates at block 1,371,000 on September 4, 2024, requiring all node operators, miners, exchanges, and wallet users to upgrade to v0.14.18.0. The upgrade permanently repairs an August vulnerability in Spark that could, under specific conditions, allow forged coins and inflate FIRO's supply, and it restores normal multi-input Spark spending. A proof-of-supply-inflation flaw in a privacy protocol is a serious security event because it directly threatens the token's scarcity and user trust. The fork also highlights how a small privacy coin must rapidly coordinate nodes, exchanges, and users to neutralize a critical vulnerability before it can be exploited. The vulnerability was disclosed on August 13 and did not compromise wallets, keys, or single-input spends, though a researcher had minted about 200 FIRO on mainnet in a controlled test. As an interim defense, v0.14.17.2 restricted Spark spending to one input, which reduced privacy by making separate payment amounts easier to correlate, until v0.14.18.0 introduced a versioned Chaum V2 proof and transaction format to fix it.

    LND cooperative-close flaw puts old nodes at full channel wipeout risk

    LND disclosed a cooperative-close vulnerability on Aug. 13 that could let a malicious peer drain a full channel balance using a one-block reorganization and an old revoked commitment. The official fix only ships in LND 0.21.0, so standard releases below 0.21.0 remain exposed unless separately patched. Because LND underpins the majority of Lightning Network nodes, a reproducible full-balance loss scenario is a serious security risk even with no known exploit. Operators on older releases must treat their nodes as vulnerable and upgrade to 0.21.0 or later to stay protected. Before the fix, LND forgot a cooperatively closed channel after its closing transaction received one confirmation, leaving the node unable to broadcast penalty transactions if a reorganization removed that confirmation and a peer published a revoked commitment. The maximum loss is the channel's full balance, and no affected users or in-the-wild exploits have been confirmed.
